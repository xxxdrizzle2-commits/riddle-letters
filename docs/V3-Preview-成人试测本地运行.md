# V3 成人试测：本地运行与线上登录

## 当前站点与边界

- V3 成人试测站：<https://riddle-letters-v3.pages.dev/>。这是独立的 Cloudflare Pages 项目 `riddle-letters-v3`，使用 `dev` 分支的 `npm run build:v3-preview` 产物手动部署；网页入口可直接打开，进入角色后用对应试测账号登录。
- V2 公开演示站：<https://riddle-letters.pages.dev/>。它从 GitHub `main` 自动执行默认 `npm run build`，继续使用浏览器本地合成数据，不与 V3 的 D1 数据库互通。`main` 已同步 V3 MVP 源码，但默认构建仍是 V2 演示模式。
- 已部署的 V3.2 冻结站点使用四个成年人持有的合成角色账号。当前实验分支的本地播种脚本改为五个成人账号：小朋友、志愿者、老师、普通运营和独立保护运营，仍只有四种前台角色；新增账号用于验证举报运营时的绕行和回避。人物与书信均为合成内容。不要把密码提交到 GitHub 或发到公开群组。

当前 V3 不使用 Cloudflare Access 作为试测者登录步骤。旧的 Access 配置说明已失效；部署专属子域名可能仍出现 Access 页面，试测时使用上面的固定站点地址。网页外壳可公开打开，但信件、结对和操作接口必须由试测账号会话及服务端角色权限校验。没有开放公众注册，也不要让真实儿童参与本轮试测。

## 线上试测怎么进入

1. 打开 V3 固定地址，选择分配的角色。
2. 从私下收到的账号资料中取出该角色的邮箱和密码，登录。不要把密码写进反馈截图。
3. 两人一组时，一人用手机、一人用电脑，同时以**不同角色账号**登录；按 [V3 成人试测任务单](./V3-成人试测任务单.md) 完成同一轮书信，观察另一台设备是否及时看到新状态。
4. 退出后再换角色。共用设备上不要保留登录状态；试测数据只写合成内容。

健康检查地址是 `https://riddle-letters-v3.pages.dev/api/health`；`200` 且 `apiReady: true` 只表示已部署试测 API 与数据库基础表可用，不能代替完整操作和权限测试，也不能证明当前实验分支已经上线。已部署站点仍按冻结版文字书信及老师文字代录理解；付费图片转换与私有 R2 尚未接入。

## 本机运行

1. 安装锁定依赖后，将 `.dev.vars.example` 复制为 `.dev.vars`，设置只用于本机的随机 `BETTER_AUTH_SECRET`（至少 32 个随机字符）。`.dev.vars` 已在 Git 忽略规则内。
2. 执行 `npm run db:v3-preview:migrate`，为本机 D1 应用迁移。
3. 执行 `npm run v3:seed-test-accounts`，输入 `ADULT-ONLY` 并按交互提示建立五个成人合成账号，其中两个都是运营角色但权限包不同。脚本还建立合成学校和限期老师指派。密码以哈希写入本机数据库，脚本不把明文保存到源码。不要输入真实儿童或真实参与者资料。
4. 执行 `npm run dev:v3-preview`，打开 `http://127.0.0.1:8788`。本机服务只监听 `127.0.0.1`，本机 D1 与线上试测 D1 分开。

线上既有账号不能自动用于本机；本机脚本建立的账号也不会出现在远程站点。不要把 `.dev.vars` 或本机数据库复制到远程环境。

## 更新与回滚

更新 V3 前确认部署目标为 `riddle-letters-v3`，使用 `dev` 的 V3 模式构建，并先完成构建与浏览器闭环检查。推送 `main` 会触发 V2 项目 `riddle-letters` 的自动部署，必须另行检查默认构建和公开站。代码锚点：`v3` 指向 `fbfb0fe`，`v3.1` 指向 `36277b5`，最终 MVP 使用 `v3.2-mvp`；旧标签不移动。

Cloudflare Pages 的部署可回退网页与 Functions 代码；**回退代码不会自动回退 D1 数据**。如有数据库迁移，先核对旧代码与现有表结构是否兼容，并保留备份与变更记录。试测结束后由项目负责人决定测试账号停用及合成数据清理，不将试测 D1 绑定到 V2 站点。
