# 业务与儿童保护边界：第二阶段实现与回滚

更新日期：2026-10-30  
适用范围：`business-safety-first-increment` 分支的成人合成数据环境。本文是工程实现说明，不是法律意见，也不授权真实儿童试点或生产部署。

## 1. 硬闸门

- 四个前台角色仍由成年人使用合成身份扮演；示例学校、孩子、书信和求助均为虚构内容。
- 真实儿童出站纸信的拍摄、OCR、人工查阅和收件展示仍保持关闭。合作学校与法律专业人员未逐项书面确认前，不得用本实现采集真实儿童原稿。
- 当前改造不部署，不修改线上 Cloudflare 绑定。`wrangler.v3-preview.jsonc` 只用于本机隔离数据库。
- OCR 只提供成年合成样本的离线结果契约、本地人工忠实转写和双视图交互，不自行安装模型，不调用外部 OCR 服务，也不把“模型运行完成”解释为内容可放行。

## 3. 领域对象与权限落点

| 对象 | 实现目的 | 关键约束 |
| --- | --- | --- |
| `School` | 区分学校责任范围 | 暂停学校不能产生新的有效老师授权。 |
| `TeacherAssignment` | 给老师限期、按孩子和任务授权 | 读取时同时检查学校、孩子、scope、开始／结束时间与撤销状态；旧 `Pair.teacherId` 只作迁移兼容。具有效 `paper-delivery` 指派的老师可立即停止本校 Pair 交付并上报异常，但不能自行恢复。 |
| `Pair` | 一名孩子与一名志愿者的独立私人关系 | 同一双方同时至多一条 active／paused Pair；孩子和志愿者都可拥有多条不同 Pair。 |
| `Letter` | 固定一封信的一组 Pair、作者、唯一收件人和逐封路线 | 保存后不得更换 Pair、作者、收件人、原信或 `deliveryRoute`。孩子到志愿者只能 online；志愿者到孩子可逐封选 online 或 school-paper。 |
| `DeliveryEvent` | 追加记录投递事实 | 审核、打印尝试／成功、实际交付、线上打开和见证阅读互不推断。恢复 Pair 不自动投递暂停期间的获准信。 |
| `HelpCase` | 与普通逾期分离的保护个案 | 不要求 Pair；按 owner／backup 分派；被反映者和回避集合不能读取、认领、转派或结案。 |
| `AccessAuditEvent` | 记录敏感读取及拒绝 | 记录操作者、目的、对象、版本、结果和时间；写审计失败时不返回敏感内容，不受普通写操作日志截断规则影响。 |
| `ManuscriptAsset`／`OcrRun` | 区分原稿、OCR 行和获准遮盖副本 | 原件、机器文字、忠实校订和获准副本不互相覆盖；每行保留页码、归一化坐标、置信信息与不确定标记。 |

## 4. 服务端读取边界

`GET /api/snapshot` 只承担首页、队列和状态展示。老师和运营收到的信件正文、附件标识、审核意见和提交历史应被清空；原稿与 OCR 列表不进入普通快照。

敏感内容改为逐对象请求：

- `GET /api/letters/:id`：作者／获准收件人、具体捕获协助任务、具体待打印任务，或被分派的待审成人草稿可以读取。非作者收件人和打印老师只取得最终获准当前版本，不含退回历史、审核说明、审核员或任务内部字段；Pair 一旦暂停或结束，老师的待打印读取立即撤权。老师不能搜索历史全文；普通运营身份不能读取。
- `GET /api/help-cases/:id`：求助者本人只能取得自己的原始提交与接报状态，不取得处理人、替补、回避名单、内部历史或结案笔记；未涉事且被分派的 owner／backup，或具有效校内保护指派的老师仅在个案未结案时读取完整案卷。结案即撤销上述处理人正文访问。类别为“运营”时要求独立保护授权；只知道“涉及老师”但不知道姓名时，正文不自动下发给任何老师，先由独立平台保护人员澄清回避关系。
- 私有附件读取使用与所属信件同一套逐对象判权，并记录允许或拒绝的读取审计；R2 key 不返回客户端，响应使用 `private, no-store`。

前端隐藏按钮不是授权。所有对象 ID、Pair ID、收件人 ID、版本 ID 和图片 ID 都必须在服务端重新关联核验。

## 5. 两个纸信方向

### 孩子纸信到志愿者

1. 老师在有效 `capture` 指派下选择孩子和准确 Pair。
2. 本轮只允许合成图片；私有保存不产生打印或实际交付事件。
3. 本地 Demo 用人工忠实转写模拟受控 OCR 结果并逐行保存；离线脚本可规范化成年合成样本的模型结果。原稿、文字和获准展示副本保持不同对象，不能用转写覆盖原文。
4. 两份副本均通过隐私／内容检查并固定版本后，才可产生 `online-available`。
5. 只有该 Pair 的唯一志愿者可读；打开后追加 `online-read`。

### 志愿者网页信到无设备孩子

1. 志愿者选择 Pair 并逐封选 `school-paper`，提交成人草稿。
2. 被分派审核员读取该版本并作通过、退回或暂缓决定。
3. 负责老师取得该封获准打印版；打印尝试和成功分别记录。出现异常时，负责老师可将该 Pair 置为“学校停止交付”的保护性暂停，立即撤销后续打印／交付读取与操作；恢复仍由平台结对岗复核执行。
4. 实际交到孩子手中后追加 `handed-to-child`；失败留在原任务重试，不新建信。
5. 孩子愿意阅读时，老师另记 `witnessed-read`。打印、交付和阅读不能互相代替。

## 6. 迁移与回滚

`migrations/0003_business_safety.sql` 采用附加式迁移，新增学校、老师指派、保护个案、投递事件、手写资产、OCR 运行和敏感读取审计表；为 Pair 与 Letter 增加必要索引／字段。迁移前必须导出 D1，并在隔离数据库演练：

1. 应用 0000 到 0003，检查表、索引和约束。
2. 导入迁移前备份，核对记录数、Pair 收件人和历史状态。
3. 无法证明具体投递事实的旧记录标为兼容数据，不补造打印、实际交付或阅读事件。
4. 运行 N:N、跨校、离任撤权、求助回避、错 Pair 和双方向投递测试。
5. 恢复演练从迁移前导出或 D1 Time Travel 开始；代码回退不等于数据库回退。

应用回滚时保留迁移后产生的投递与审计记录；不得用旧代码覆盖或截断新事件。对象存储另保留清单和版本，数据库恢复与对象恢复分别验收。

2026-10-30 已在 D 盘隔离的本机 D1 上从 0000 依次应用到 0003，确认新增表可查询，并确认更新敏感读取审计记录会被 `access audit is append-only` 触发器拒绝。这只证明本机迁移和约束行为，不等于远程 D1 已迁移或可恢复；发布前仍须另做导出、导入和 Time Travel 恢复演练。

## 7. OCR 离线与本地合成交互

协议见 [OCR 成年合成样本离线实验协议](./OCR-成年合成样本离线实验协议.md)。`scripts/ocr-offline.py` 可规范化 PaddleOCR 官方输出，保留原始识别文字、页码、行坐标、置信度、SHA-256 和 `humanReviewRequired=true`；它不润色、不猜字、不自动放行。输出与模型缓存必须放在 D 盘任务目录。

本地 Demo 的成年合成流程还会在审核时要求“忠实转写确认”和“图像隐私确认”，并复制成不同附件 ID 的展示副本，用来验证权限、版本绑定和页面交互。这个复制动作没有真正移除图片中的电话、二维码、边角文字或元数据，**只能用于内容已知的合成图片**；正式模式还要求原稿和 `approved-redacted` 资产分别存在于不同私有对象、获准附件绑定该副本、OCR 的原稿 ID 与 SHA-256 一致且完成人工复核，否则直接阻断。当前尚无满足这些条件的正式云端管线。

收件展示使用互斥的“清晰转写”和“手写原稿”视图，不能并排。点击疑难行可以切换到获准原稿副本并定位；定位失败时仍可普通切换。转写已遮盖但图片未遮盖、二维码未检查、边角漏字或图片元数据未处理时，一律不产生收件人可读版本。
