## 1. 结论摘要

闭环可以成立，但需要三件事同时落地，缺一不可：

1. **判权收敛**：新增 `src/policy.ts` 作为唯一入口，`domain.ts` 与 `server/core.ts` 都改成「先 policy → 再执行」。页面不再写角色判断，只读 `capabilities.ts`。
2. **状态可走通**：`0004` 迁移 + 9 张新表 + 12 条命令 + 种子场景，使「授权 → 读取 → 破窗 → 复核 → 报告 → 争议 → 恢复」每条路都有出口，失败路径也有可读原因。
3. **可被证明**：`invariants.ts` 的 11 条不变量 + 12 项单元 + 3 条新增 e2e，让「跨校不可读」「破窗不可连开」「报告不全不可关案」「争议未裁决不可恢复」这些规则由测试而不是由文案保证。

本轮**不重写** `domain.ts` / `core.ts` 的结构，只在既有 `reduceCommand` / `executeCommand` 分支内接入 policy 与守卫。

## 3. 架构改造

### 3.1 依赖方向

```
页面 (Operations / Companions / Account / Shell)
   │  只读 capabilities.ts  ──────────────┐
   │  只 dispatch(命令)                    │
   ▼                                       │
src/data.ts dispatch ──► src/domain.ts reduceCommand
                              │   └──► src/policy.ts（判权）
                              │   └──► src/invariants.ts（仅测试/自检页）
                              ▼
server/core.ts executeCommand ──► src/policy.ts（同一判权）
                              └──► scopeState / snapshot（元数据）
```

约束：

- `policy.ts` 是**纯函数**，不读 I/O、不打日志、不抛异常；输入 `AppState`，输出 `allow | deny`。
- 服务端在 policy 之外包一层审计；审计失败**不返回内容**（沿用 `auditedRead` / `appendAccessAudit`）。
- `invariants.ts` 也只读状态，供测试与「系统自检」页使用，不参与写路径。

### 3.2 `src/policy.ts`

```ts
export type PolicyAction =
  | 'read-overview' | 'read-letter' | 'read-attachment' | 'read-help-case'
  | 'read-risk-signal' | 'read-dispute' | 'read-grant'
  | 'report-abnormal' | 'open-case'
  | 'grant-access' | 'revoke-access'
  | 'open-emergency-access' | 'review-emergency-access'
  | 'update-help-report' | 'escalate-help-case' | 'resolve-help-case'
  | 'open-dispute' | 'decide-dispute'
  | 'review-risk-signal' | 'complete-support-task' | 'complete-training'
  | 'match' | 'write-letter' | 'pause-volunteer' | 'resume-pair' | 'record-delivery'

export type PolicyPurpose =
  | 'home-overview' | 'deliver-print' | 'child-assisted-capture'
  | 'safeguarding-case' | 'emergency-risk' | 'audit-review' | 'data-request'
  | 'content-review' | 'pair-management'

export type PolicyReasonCode =
  | 'RESOURCE_NOT_FOUND' | 'ROLE_NOT_PERMITTED' | 'NO_PERMISSION_PACKAGE'
  | 'NO_ASSIGNMENT' | 'ASSIGNMENT_EXPIRED' | 'WRONG_SCHOOL'
  | 'PAIR_NOT_ACTIVE' | 'EXCLUDED_ACTOR' | 'NOT_REVIEWER'
  | 'NO_SCHOOL_AUTHORITY' | 'SECOND_SIGNATURE_REQUIRED' | 'SIGNATURE_CONFLICT'
  | 'GRANT_NOT_FOUND' | 'GRANT_EXPIRED' | 'GRANT_REVOKED' | 'PURPOSE_MISMATCH'
  | 'EMERGENCY_OUTSTANDING' | 'EMERGENCY_WINDOW_EXCEEDED' | 'BREAK_GLASS_SELF_REVIEW'
  | 'TRAINING_REQUIRED' | 'CAPACITY_EXCEEDED' | 'COOLDOWN_ACTIVE'
  | 'SAFETY_PAUSE' | 'OPEN_DISPUTE' | 'REPORT_FIELDS_INCOMPLETE'
  | 'NOTE_TOO_SHORT' | 'NO_DUTY_BACKUP'

export type PolicyDecision =
  | { decision: 'allow'; grantId?: string; reasonCode?: never }
  | { decision: 'deny'; reason: string; reasonCode: PolicyReasonCode }

export interface PolicyResource {
  type: 'letter' | 'attachment' | 'help-case' | 'overview'
  | 'risk-signal' | 'dispute' | 'pair' | 'grant' | 'support-task' | 'training' | 'none'
  id?: string
}

export interface PolicyInput {
  actor: Person
  action: PolicyAction
  resource: PolicyResource
  purpose: PolicyPurpose
  state: AppState
  now: string          // 一律取 state.clock 或调用方注入的 now
}

export function authorize(input: PolicyInput): PolicyDecision
```

实现要点：

- **资源一律按 id 回查 state**，不信任调用方传入的 pairId / recipientId / versionId。查不到 → `RESOURCE_NOT_FOUND`。
- 老师判权统一走一个内部函数 `teacherAssignment(state, teacherId, schoolId, childId, scope, now)`，同时校验 `startsAt <= now < endsAt` 且 `revokedAt` 为空、学校 `status === 'active'`。`domain.ts` 现有 `hasTeacherScope` 改为该函数的薄封装；`server/core.ts` 的 `teacherHasScope` 同样委托，消除两套实现。
- 授权（`access_grants`）判权：`targetType + targetId + actorId + purpose` 命中、`startsAt <= now`、`expiresAt > now`、`revokedAt` 为空、非 emergency 时 `approved_by` 非空。
- 回避集合：`helpCase.excludedActorIds` 命中即 `EXCLUDED_ACTOR`，包括 owner / backup / 争议裁决人。
- 破窗：`open-emergency-access` 只允许 `safeguarding` 或有效 `safeguarding-lead`；`expiresAt - startsAt <= 2h`；存在同 actor 未复核且未超时记录 → `EMERGENCY_OUTSTANDING`。
- 争议恢复：`resume-pair` 若 `pauseHistory` 末条 `reason === 'safety-risk'` 且存在未决定争议 → `OPEN_DISPUTE`；否则要求 `dispute_cases.status === 'decided'` 且 `school_decision_by` 与 `platform_decision_by` 非空且不同。

`domain.ts` 改法（最小侵入）：

| 现有 | 改为 |
| --- | --- |
| `canReadLetter(state, actor, letter)` | `authorize({action:'read-letter', resource:{type:'letter',id:letter.id}, purpose: 推断, ...})` 的薄包装 |
| `canHandleHelpCase(...)` | `authorize({action:'read-help-case', ...})` |
| `eligibleHelpOwner(...)` | 复用 policy 的 `safeguarding` owner/backup 判定 |
| `scopeState` 内逐对象保留 | 对每封信 / 每个附件 / 每个个案都调 policy；deny 即清空（保持现有输出形态） |

`DomainError` 不扩展枚举，改为 `new DomainError(decision.reason, 'FORBIDDEN')`：`message` 直接给页面可读原因。服务端 `executeCommand` 捕获后仍映射为 `ServiceError('FORBIDDEN', message)`，前端文案不变。

### 3.3 `src/capabilities.ts`

只读能力表，页面**不得**再写 `actor.role === ...` 判断按钮。

```ts
export interface Capabilities {
  canReportAbnormal: boolean          // 老师：有效 paper-delivery / protect 指派且学校 active
  canOpenCase: boolean                // protect 老师 或 safeguarding owner/backup（非回避）
  canApproveSensitive: boolean        // 有效 safeguarding-lead 或 privacy 运营
  canBreakGlass: boolean              // safeguarding 或有效 safeguarding-lead，且无未复核破窗
  canReviewBreakGlass: boolean         // privacy 且当前无本人开启的待复核记录
  canDecideDispute: boolean           // 学校负责人 + 平台保护/结对岗（按侧签名）
  canOpenDispute: boolean             // 学校负责人 或 matching 运营
  canReviewRiskSignal: boolean        // safeguarding，且信号涉己时不可复核
  canCompleteSupportTask: boolean     // 该任务 owner 老师且指派有效
  canCompleteTraining: boolean        // 志愿者本人且当前版本未完成
  canViewSystemCheck: boolean         // privacy
  canManagePairs: boolean             // matching
  canManageTraining: boolean          // accounts / safeguarding
  canSeeDeliveryActions: boolean      // 有效 paper-delivery 指派且结对未处于安全暂停

```

实现方式：内部对代表性资源调用 `authorize`（资源无关项用 `type:'none'`），保证能力表与判权永不漂移。页面只 `const caps = capabilitiesFor(actor, state, state.clock)`。

### 3.4 `src/invariants.ts`

```ts
export type InvariantRule =
  | 'PAIR_VALIDITY' | 'LETTER_IDENTITY' | 'PAPER_EVENT_ORDER'
  | 'CASE_REPORT_COMPLETE' | 'EXCLUSION_CLEAN'
  | 'GRANT_LIFECYCLE' | 'EMERGENCY_REVIEWED' | 'DELIVERY_DURING_SAFETY_PAUSE'
  | 'PAIR_UNIQUE' | 'PAUSE_METADATA' | 'RISK_SIGNAL_RESOLVED'

export interface InvariantViolation {
  rule: InvariantRule
  severity: 'high' | 'medium'
  message: string
  refs: string[]     // pair/letter/case/grant id，便于页面跳转
}

export function checkInvariants(state: AppState): InvariantViolation[]
```

10 条判定细则：

| 规则 | 判定 | 级别 |
| --- | --- | --- |
| `PAIR_VALIDITY` | active pair 的孩子/志愿者账号 `accountStatus` 非 `disabled`，学校存在且 `active`，负责老师有未过期 `status` 指派 | high |
| `LETTER_IDENTITY` | `pairId` 存在，`authorId` 与 `recipientId` 是该 pair 的两端，收件人 = `recipientForLetter()` 结果 | high |
| `PAPER_EVENT_ORDER` | 纸质信事件序列必须是 `approved(letter.moderation) → printed → handed-to-child → witnessed-read`；出现 handed 无 printed、witnessed 无 handed、printed 早于 approved 即违规；`print-attempt` 失败不算 printed | high |
| `CASE_REPORT_COMPLETE` | `severity='high'` 且 `status='resolved'` 时：`report_decision='not-required'` 需 `report_reason` 且 `report_reviewed_by` ≠ `ownerId`；否则需 `reported_at` + `report_authority` + `report_receipt` | high |
| `EXCLUSION_CLEAN` | `ownerId` / `backupOwnerId` / `schoolOwnerId` 不在 `excludedActorIds`；`dispute_cases.school_decision_by` 不在涉及个案回避集合 | high |
| `GRANT_LIFECYCLE` | 无「`expiresAt < clock` 且 `revokedAt` 为空」的 grant；`targetType/targetId` 指向的对象仍存在 | medium |
| `EMERGENCY_REVIEWED` | 无 `emergency=true` 且 `reviewDueAt < clock` 且 `reviewedAt` 为空的 grant | high |
| `DELIVERY_DURING_SAFETY_PAUSE` | pair 处于安全暂停期间（`pauseHistory` 末条未结束），不得有新的 `printed / handed-to-child` 事件落在暂停区间内 | high |
| `PAIR_UNIQUE` | 无重复 `active|paused` 的 (childId, volunteerId) 组合 | high |
| `PAUSE_METADATA` | 每条未结束暂停都有 `reason`、`actorId`、`reviewDueAt`；安全暂停须关联争议或个案 | medium |
| `RISK_SIGNAL_RESOLVED` | 所有 `severity='high'` 信号 `status ∈ {'actioned','dismissed'}`，且 `dismissed` 必须有 `action` 备注 | medium |

展示：运营「系统自检」页按 level 分组，显示规则名、可读说明、refs 链接；种子数据必须为 `[]`。

## 4. 数据模型

### 4.1 迁移 `migrations/0004_safeguarding_closed_loop.sql`（DDL 草案）

沿用 0003 风格：`CREATE TABLE IF NOT EXISTS` + 索引 + 可空列 `ALTER` + 追加型触发器。所有时间列用 ISO 8601 文本，判定一律在应用层用 `state.clock` 比较（SQLite 不能表达「现在」）。

```sql
-- 1) 学校负责人授权包
CREATE TABLE IF NOT EXISTS app_school_authorities (
  id TEXT PRIMARY KEY,
  school_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('principal','safeguarding-lead')),
  backup_user_id TEXT,
  starts_at TEXT NOT NULL,
  ends_at TEXT,
  revoked_at TEXT,
  approved_by TEXT NOT NULL,
  data_json TEXT NOT NULL,
  CHECK (backup_user_id IS NULL OR backup_user_id <> user_id),
  CHECK (ends_at IS NULL OR ends_at > starts_at)
);
-- SQLite 不能按「当前时刻」建部分唯一索引；用「未撤销」近似 + 命令守卫 + 不变量补时间重叠
CREATE UNIQUE INDEX IF NOT EXISTS app_school_authorities_one_lead
  ON app_school_authorities(school_id) WHERE kind='safeguarding-lead' AND revoked_at IS NULL;

-- 2) 限期访问授权
CREATE TABLE IF NOT EXISTS app_access_grants (
  id TEXT PRIMARY KEY,
  actor_id TEXT NOT NULL,
  target_type TEXT NOT NULL CHECK (target_type IN ('letter','attachment','help-case','overview')),
  target_id TEXT NOT NULL,
  purpose TEXT NOT NULL,
  reason TEXT NOT NULL,
  granted_by TEXT NOT NULL,
  approved_by TEXT,
  starts_at TEXT NOT NULL,
  expires_at TEXT NOT NULL,
  emergency INTEGER NOT NULL DEFAULT 0,
  review_due_at TEXT,
  reviewed_at TEXT,
  reviewed_by TEXT,
  review_outcome TEXT CHECK (review_outcome IN ('upheld','revoked')),
  revoked_at TEXT,
  data_json TEXT NOT NULL,
  CHECK (expires_at > starts_at),

);
CREATE INDEX IF NOT EXISTS app_access_grants_actor ON app_access_grants(actor_id, expires_at);
```

## 5. 读取路径与判权矩阵

| 路径 | 目的 | 允许谁 | 对象范围 | 失效条件 | 审计 |
| --- | --- | --- | --- | --- | --- |
| A 元数据 | `home-overview` | 有效 `status` 指派老师；对应授权包运营 | 结对、进度、逾期、积压、暂停原因 | 撤权 / 到期 / 跨校 | `teacher-overview` allowed/denied |
| B 当次协助 | `child-assisted-capture` / `deliver-print` | 有效 `capture` / `paper-delivery` 指派老师 | **仅该封**（`access_grants.targetId` 或当前 `tasks` 指向的 letterId） | 任务结束、pair 暂停/结束、grant 到期 | `letter` |
| C 保护个案 | `safeguarding-case` | `protect` 指派老师（`schoolOwnerId`）；`safeguarding` owner/backup | 该案卷 | 结案、回避、撤权 | `help-case` |
| D 紧急破窗 | `emergency-risk` | `safeguarding` 或 `safeguarding-lead` | **单个对象** | `expiresAt`（≤2h）、复核 `revoked` | `severity='high'` + `grantId` |

明确禁止（写成 policy 的 deny 分支，而不是 UI 隐藏）：

- 老师读本校全部信件正文：A 路径只给元数据；B 路径 `targetId` 非本任务 letterId → deny。
- 老师搜索历史全文：无「按关键字查信件」的 action；`scopeState` 不返回历史版本。
- 运营日常巡检读儿童正文：`read-letter` 仅 `content-review`（分派给本人的待审版本）与 B/C/D 允许；`safeguarding` 运营也不能在无个案/授权时读正文。
- 任何人读自己回避的个案：`EXCLUDED_ACTOR` 优先于所有其他 allow。
- 页面隐藏按钮不算授权：所有写/读命令在服务端重新 `authorize`。

学校与平台的双签名建模（统一为「一侧一次签名，齐了才生效」）：

| 场景 | 第一签名 | 第二签名 | 生效判定 |
| --- | --- | --- | --- |
| `grant-access`（敏感对象：`help-case`、`audit-review`、`data-request`） | `safeguarding-lead` 或教师侧授权人 | `privacy` / `safeguarding` 平台侧，且 ≠ 第一签名 | 两次调用写同一 `grantId`，`approved_by` 为空时 `policy` deny `SECOND_SIGNATURE_REQUIRED` |
| `decide-dispute` | 学校负责人写 `school_decision_by` | 平台 `safeguarding`/`matching` 写 `platform_decision_by` | 两个字段非空且不同人、`decision` 一致，才 `status='decided'` 并允许恢复 |
| `open-emergency-access` 的复核 | 开启者（不参与复核） | `privacy` 且非开启者 | `review-emergency-access` 写 `reviewed_*` |

`grant-access` 的 `grantId` 由客户端生成（`crypto.randomUUID()`）并随命令传入，服务端校验格式与「同一 `grantId` 只能续签、不能改 `target`/`purpose`」，防止借续签替换对象。

敏感读取的审计闭环（服务端）：

```
authorize (policy) ──deny──► appendAccessAudit(denied, reasonCode) ──► 抛 403 可读文案
                   └─allow─► appendAccessAudit(allowed[, grantId, severity])
                              └─写失败─► 抛 AUDIT_UNAVAILABLE，不返回内容
```

`snapshot` 卫生（`server/core.ts` `scopeState`）：

- 保留：pair、letter 的 id/pairId/authorId/recipientId/moderation/updatedAt/deliveryRoute、task、delivery 时间、deliveryEvent、helpCase 标题级字段、新增 9 表的元数据。
- 清空：`body/title/riddle*`、`attachmentId`、`manuscriptAssetId`、`ocrRunId`、`approvedRenditionId`、`submissionVersions`、`moderationNote`、`helpCase.body/resolution/history`、`grant.reason`（理由含敏感描述时按角色裁剪）。
- 新增表在 `snapshot` 中也要过滤：老师只看到自己学校 + 自己负责孩子的 `supportTasks/riskSignals(涉及自己孩子)/disputeCases(自己学校)`；运营按授权包。

## 10. 风险与回归点

### 10.1 现有测试受影响清单

- 种子新增 `t3/t4/v3/v4`、4 条 Pair、`planPolicies`：任何断言「people 数量」「pairs 长度」「默认 actor 可选伙伴」的用例需复核。
- `data.test.ts` 中 `match` 相关用例：新增容量/冷却守卫后，原本能创建的配对可能被拒；需改用 `v3` 或临时提高 `planPolicies`。
- `server/core.test.ts` 的 `help-case` 审计序列 `['denied','denied','allowed','allowed','denied','allowed']`：若 `scopeState` 改为逐对象 policy，调用次数可能变化，需重新按行为而非次数断言。
- `tests/demo.spec.ts` 的老师首页文案与区块顺序：P3 重排后选择器需同步；建议按 `data-testid` 或 `role` 断言，减少文案耦合。
- `snapshot` 新增表的过滤：老师快照若暴露 `riskSignals` 中的其他孩子 pairId，会违反「A 路径只给元数据」的本意，需按学校/孩子过滤。

### 10.2 设计与实现风险

| 风险 | 缓解 |
| --- | --- |
| 双签名退化成「一人代签」 | 服务端校验 `approved_by ≠ granted_by`，且校验第二签名人当前具备对应授权包与在任状态；e2e 覆盖「单侧签名不可恢复」 |
| `policy` 与 `reduceCommand` 双重判断导致规则分叉 | 只允许 `executeCommand` 做「账号/角色/权限包/请求格式」粗检；所有对象级判断只在 `reduceCommand` 内调 `authorize` |
| 新表漏注册导致云端静默丢数据 | P0 完成后跑一次 `dev:v3-preview` + `db:v3-preview:migrate`，手工写入一条 grant/信号后刷新核对 |
| 破窗被当成「常态阅卷通道」 | 单对象 + ≤2h + 高审计 + 24h 复核 + 未复核拒绝第二次；不变量 `EMERGENCY_REVIEWED` 兜底 |
| 自动检测被当成结论 | 风险信号只是「提示」，处置必须人工 `review-risk-signal`；页面文案保留「不能保证没有恶意」 |
| 时间源不一致 | 全部用 `state.clock`；服务端 `now` 写入 `store.state.clock`；不变量与 policy 都接收 `now` 参数 |
| 无障碍回退 | 新页面沿用既有 `focus-visible`、44px、`prefers-reduced-motion` 静态替代；e2e 保留 axe 检查 |

## 11. 仍未做 / 需确认（规划内明确列出）

1. **法律路径**：儿童出站纸信的拍摄、OCR、人工查阅与展示，仍需法律专业人员就《未成年人保护法》第 63 条、《学校保护规定》第 10 条出具书面结论；本轮只做成年合成数据。
2. **真实学校授权**：`school_authorities` 仅是数据结构与演示授权，不构成真实学校的书面委派；真实试点前需学校出具负责人、替补、任期与联络方式。
3. **值守与 SLA**：种子里的值班表是合成数据；真实响应时限、备岗、升级电话链需运营与学校共同确认。
4. **报告渠道**：`report_authority` / `report_receipt` 只记录字段，不接公安、民政、检察等真实渠道；强制报告的具体对接方式需法律与机构确认。
5. **证据保全**：`evidence_snapshots` 只存合成摘要，不做真实原稿/附件私有存储与不可逆遮盖；真实证据链需 R2 私有桶、版本与保留期策略。
6. **争议裁决权限**：谁代表「平台」签字（保护岗还是结对岗）、是否允许同一人兼两校，需组织决策。
7. **删除与保留期限**：`0004` 未定义数据保留期与删除流程；个保法影响评估前不定稿。
8. **未部署**：本轮不产生 Preview/生产变更，不推送 `main`/`dev`，也不改远程 D1。
