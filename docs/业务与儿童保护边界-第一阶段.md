## 2. 四角色的职责、决定权和可见范围

四个角色继续作为独立的前台身份。监护人是参与授权、撤回和知情的重要主体，但本阶段不新增第五个前台工作区。“小朋友＝志愿者＜老师＜运营”不能当作内容权限的继承链；学校和平台是两条不同的责任线。

| 角色／内部授权包 | 主责与可作的决定 | 正常可见的范围 | 不因身份自动获得 |
| --- | --- | --- | --- |
| 小朋友 | 自愿参加、主动写信、选择回应、申请暂停或退出、求助 | 自己参加的结对、自己的草稿及获准送达给自己的信 | 其他孩子资料、伙伴与其他人的通信、未审核的成人来信 |
| 志愿者 | 经准入和培训后在各自结对写信、回应、申请暂停 | 自己参与的每条结对及属于该条关系的获准往来 | 孩子真实姓名、电话、住址、精确学校位置、其他伙伴的信或私聊入口 |
| 指派老师 | 核实学校侧参与条件，了解负责孩子的结对状态，协助当次纸信收发；可立即停止本校实际交付并上报 | 负责孩子的必要身份映射、结对与任务元数据；在合法授权范围内接触当次操作所必需的内容 | 全校历史书信正文、私人求助全文、自己代传信的审核通过权 |
| 校内协调负责人（老师身份内授权） | 安排学校内负责人和替补，确认校内承接能力及保护事件交接 | 本校必要的结对容量、任务和异常状态 | 因能看总览而查阅所有通信 |
| 结对／账号管理员（运营身份内授权） | 核验志愿者资格、执行结对、停用平台账号 | 跨学校必要的准入和结对元数据 | 内容审核权及全部书信正文 |
| 内容审核员（运营身份内授权） | 审核分派给自己的、尚未投递的成人草稿；必要时暂缓或退回 | 所分派版本及判断所需的上下文 | 无理由检索全部历史、审核自己的信件或处理针对自己的投诉 |
| 儿童保护负责人（运营身份内授权） | 接手受限风险案件，决定平台阻断措施，协调学校指定负责人 | 被分派案件和必要证据；敏感访问留痕 | 普通运营身份下的全部儿童资料 |
| 隐私处理负责人（运营身份内授权） | 核实并处理访问、更正、撤回、删除或泄露事件 | 处理申请所必需的数据与记录 | 内容审核和结对决定权 |

每次服务端读取或操作都应同时判断**角色与授权包、学校范围、结对、信件状态、操作目的、授权期限及案件回避**。前端隐藏按钮不能替代服务端判权。上述精细授权是目标设计，当前 V3.2 尚未全部做到。

## 3. 学校与平台的管理关系

| 事项 | 学校／老师负责 | 平台运营负责 | 交接完成条件 |
| --- | --- | --- | --- |
| 儿童加入 | 依法核实学校承接条件、必要的身份和监护授权事实，并听取孩子意愿 | 核对平台所需状态，不把一次勾选视为已完成真实核验 | 学校指定负责人及证据位置明确，孩子可拒绝或退出 |
| 志愿者准入 | 确认本校适配条件；学校引入校外人员时履行相应管理职责 | 核验、培训、行为约定，决定平台账号启停 | 资格有效、负责机构明确、培训完成 |
| 建立结对 | 确认孩子愿意且学校有收发和保护容量；可拒绝本校参与 | 核对志愿者资格和平台审核容量后建立一条 Pair | 双方认可，记录执行者、时间和依据 |
| 成人草稿审核 | 接触纸质交付所需的获准版本，不替平台放行自己经手的草稿 | 分派审核员在投递前作通过、退回或暂缓决定 | 固定被批准的版本；未审核或被暂缓的版本不可送达 |
| 纸质交付 | 打印、实际交付、必要的见证阅读分别确认；可以先停止本校交付 | 查看进度、协调滞留；不可越过老师声称已经交到孩子手中 | 各事件分别有实际操作者和时间 |
| 风险与退出 | 先保护孩子，启动本校规定的现实联络与报告；确认不再交付 | 停止平台传播、暂停涉事账号及相关结对、保存必要证据；协同保护负责人 | 涉事者回避；复核、外部报告、支持与回访有记录 |

平台运营不是老师的校内上级，老师也不能以学校身份替代平台审核。双方意见相左时先保持相关投递暂停，由**校方指定保护负责人和项目保护负责人**协调；恢复须记录决定人及依据。正式合作前必须写明二人的姓名、替补、联络方式、值守时间和超时升级路径，不能只写“由老师／运营处理”。

## 4. 目标书信闭环及不可混同的状态

**多对多的含义**：一个孩子可有多位志愿者，一位志愿者可陪伴多位孩子；每组仍是一条独立、私密的双人 Pair，不是群聊。同一对人同一时间仅一条有效 Pair。每封信唯一指定 Pair、作者、收件人和提交版本；新伙伴不继承旧伙伴的信。活跃数量上限由孩子负担、老师收发量和实际审核值守容量确定，而不把数据结构退回一对一。

审核状态（草稿、待审、暂缓／退回、通过）与投递状态（待线上可读／待打印、已打印、已实际交付、已打开或见证阅读）应分别建模。**审核通过≠已经送达；打印≠实际交付；交付≠已经阅读。**回应时间从确认送达起算；暂停和假期按记录顺延。成年志愿者可约定回应期限；孩子只设温和关怀窗口，由老师先了解意愿和实际情况，不产生“欠信”评价。

- **孩子写纸信给在线志愿者（待法律路径确认）**：孩子确定收件伙伴 → 授权人员选定准确的 Pair 并拍摄 → 质量检查、私有原稿与 OCR 转写 → 按合法路径完成必要检查并形成收件人版本 → 指定志愿者在线可读 → 打开另记。老师拍摄不等于能常态查阅通信；该流程当前不能用于真实儿童信件。
- **志愿者网页写信给无设备孩子**：成人提交尚未投递的草稿 → 平台审核通过并固定版本 → 老师打印 → 实际交到孩子手中后确认 → 如有见证阅读再另记 → 孩子可以选择回应。打印失败可重试，不产生第二封信。
- **暂停或异常**：收件人不明、错投风险、未审核、照片不完整、账号停用或结对暂停时停止下一步并显示由谁处理。可信的志愿者安全风险须检查并暂停其所有活跃 Pair；普通单组暂停仅影响该组。

当前代码仍将通道放在 Pair 且限制一人只有一组有效结对；以上是**第二增量**的实现规格，本阶段只确定规则。

## 5. 儿童保护与求助处置

未来真实流程采用多层阻断，不能宣称能够保证志愿者绝无恶意。禁止索要私人联系方式、地址、照片、礼物、私下见面或要求保密；不提供绕过审核的自由私聊或直寄渠道。成人草稿及其中的谜语、提示、答案和附件在交给孩子前检查，自动规则仅用于提示，不能替代人工判断。手写原稿上线后，OCR 文字与完整原图都需检查，避免漏识别区域泄露联系方式。儿童表达困难或不愿继续首先按支持和退出意愿处理，不机械地判为违规。

求助是**独立保护事项**，不以 Pair 为必填、不默认第一位伙伴，也不与普通逾期共用公开处理队列。记录求助者、可能涉事人和回避对象；仅求助者与适格、被授权的保护处理人可见全文。被反映的志愿者、老师或运营不能读取、接手、转派或关闭该案。若没有独立适格受理者，产品不得显示“已由工作人员接手”，应明确站内渠道当前不可用并引导现实渠道。真实试点必须预置未涉事的校内和项目接手人及替补；没有设备的孩子要能在线下求助。

处置顺序：**暂停相关投递和接触 → 保护负责人核实并保全必要记录 → 按风险启动学校与平台职责及法定报告渠道 → 支持孩子并确定是否继续参与 → 记录复核和后续回访**。可能涉事监护人或老师不自动收到举报内容；重大或疑似侵害不能只在站内排队。密切接触未成年人的单位及其工作人员在工作中发现相关疑似侵害或危险情形，依法负有及时报告义务；网络服务提供者也有相应的阻断、保全和报告要求。[《未成年人保护法》第11条](https://policy.mofcom.gov.cn/claw/clawContent.shtml?id=100339)、[《未成年人网络保护条例》第29、38条](https://www.cac.gov.cn/2023-10/24/c_1699806932316206.htm)

值守能力须先按“活跃 Pair 数 × 预计每周来信数 × 单封人工核查时间”核算，并写明正常时段、备岗和超时升级；未配置前不承诺即时受理或送达。

## 6. 法律与数据边界：真实儿童试点的阻断条件

**已核对的法律事实：**《未成年人保护法》（2024 年修正）第 63 条对开拆、查阅未成年人的信件和网络通讯列有严格限制；一般性的“取得监护同意后平台逐封查阅”不在列明例外之中。《未成年人学校保护规定》第 10 条也限制学校查阅学生通信。儿童主动交付开放式信件供代寄、拍摄、OCR 和风险审查的法律定性尚未有本项目可采用的书面结论；不得由产品团队自行推定合法。[2024 年修正《未成年人保护法》](https://policy.mofcom.gov.cn/claw/clawContent.shtml?id=100339)、[《未成年人学校保护规定》](https://www.moe.gov.cn/jyb_xxgk/xxgk/zhengce/guizhang/202112/t20211206_584982.html)

《个人信息保护法》将不满十四周岁者的个人信息列为敏感个人信息，并规定监护人同意、专门处理规则、最小必要措施，以及涉及敏感信息、委托处理或跨境提供等情形的事前影响评估。若学校与平台共同决定处理目的和方式，应约定各自权利义务；若平台仅受学校委托处理，则须明确委托目的、期限、方式和保护措施。两种关系不能仅凭产品角色名称判断。《未成年人网络保护条例》还规定了适用场景下的真实身份信息、工作人员最小授权、访问审批与记录等要求。[《个人信息保护法》第20、21、28、31、55—56条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)、[《未成年人网络保护条例》第31、36条](https://www.cac.gov.cn/2023-10/24/c_1699806932316206.htm)

真实试点需逐项取得或完成以下证据，缺任一项不接收真实儿童数据：

1. 合作学校、项目主体、校内及平台保护负责人和替补、有效的线下求助与报告联系方式；学校与平台对儿童加入、交付、账号、审核和数据处理的书面分工。
2. 法律专业人员结合第 63 条对儿童出站信的代寄、拍摄、OCR、人工检查与收件人展示给出书面判断；若无可执行路径，真实试点暂不把儿童信件采入平台，重新限定服务范围。
3. 监护告知与适用同意、孩子本人意愿、撤回及停止参与流程；志愿者的适用核验、培训、行为承诺和学校引入校外人员的手续。
4. 个人信息保护影响评估；原稿、转写、身份映射、备份和日志的保存期限、访问审批、删除及泄露应对；OCR 服务、Cloudflare 等供应方的数据流向与跨境问题核实。
5. 服务端按学校、具体任务及人员任期控制权限；原稿和获准遮盖版本分离、私有存储、敏感读取留痕；对错投、恶意引导、被投诉人读取和无人值守等情形做对抗演练。

当前 Cloudflare 成年合成试测和未启用的图片服务不能视为已满足上述条件。真实儿童样本不得默认进入 OCR 模型训练或公开展示。公开演示只使用虚构人物和合成内容。
