# V3 成人复测任务单（可选）

本清单保留作后续可选复测，不是冻结 MVP 的发布前任务；四个预设合成账号的内部闭环已记录在 [MVP 冻结验收记录](./MVP-冻结验收清单.md)。若以后用于论文研究，应先另定研究问题和记录方法，不把成人操作结果当作儿童使用效果。

试测地址：<https://riddle-letters-v3.pages.dev/>。四个角色均由成年人使用合成账号扮演；账号资料单独私发，不填真实儿童、学校、住址、联系方式、照片或个人经历。网页入口直接打开，再选择角色并登录，无需 Cloudflare Access。

## 安排

- 每组两人：一人手机、一人电脑，同时在线。按步骤轮流使用志愿者、小朋友、老师、运营四个**不同账号**；不要在两台设备上同时编辑同一封草稿。
- 如有两组，**两组错开时间**；每组内部的手机与电脑同时在线。四个账号及 D1 数据库是共用的，为信件标题加上组别（例如“A组的云”），避免把另一组的信误认为自己的。不要重置共享试测数据库。
- 观察者先不提示点击位置；参与者卡住时，记录页面、第一次点击、期望、实际和截图，再提供必要帮助。

## 线上书信链

1. 运营：检查是否已有结对；如未结对，建立合成小朋友与志愿者的结对，并说出下一步是谁。
2. 志愿者：在电脑上登录，找到主要任务，写一封带组别的短信，保存草稿，再预览并提交审核。提交后检查主区域是否明确显示“等待运营审核”。
3. 运营：在另一台设备上登录，找到待审信并通过。双方观察信件状态是否同步。
4. 小朋友：在手机上登录，打开来信，查看“已送达”和“已打开阅读”的记录；回到信箱，写一封回信并提交审核。
5. 运营审核回信；志愿者回到工作区，检查首屏是否提示新回信，再打开阅读。读完后确认自己的回应任务是否清楚。

## 纸质书信链

1. 运营审核纸质信。老师在电脑上先预览 A4 信纸、记录已打印，**实际交付后**再确认送达。打印不等于交付，交付也不等于打开阅读。
2. 小朋友打开已交付的来信；老师在待回传中用合成文字代录回信，让“孩子已核对”步骤完成后提交审核。
3. 运营审核回信；老师再次打印并交付这封写给志愿者的回信。交付结果应指向**志愿者**阅读，志愿者首页应提示收到回信。

## 顺手检查

- 从任务卡进入详情后，页面内“返回”是否说明目的地；浏览器前进、后退、刷新后是否仍找得到任务。
- 写信时输入未保存内容再离开，是否能选择继续写、保存后离开或放弃修改。
- 两台设备是否看到同一封信的审核、交付和阅读状态；遇到旧标签页加载失败时，刷新后能否恢复。
- 手机屏幕上按钮是否容易找到，输入键盘是否挡住提交按钮。
