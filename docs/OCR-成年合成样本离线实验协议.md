# 手写信 OCR：成年合成样本离线实验协议

状态：研究与工程协议；网站尚未具备自动 OCR 服务。当前本地 Demo 仅用人工忠实转写和合成图片验证版本、判权与双视图，不能代替模型实验或正式遮盖。只使用成年自愿作者或许可明确的数据，不收集、上传或训练真实儿童原稿。

## 数据与标注

- 每份样本记录作者代号、拍摄设备、页数、清晰度与倾斜分层、来源和许可。按**作者**划分训练、验证和测试，避免同一人的字迹跨集合。
- 两名标注者独立照原稿录入，保留错字、语气词、标点和合理换行。看不清处写统一的不可辨标记，不依上下文猜字；分歧由第三人仲裁。
- 原始图片、OCR 机器结果、人工忠实转写、获准展示副本分别保存。修改标注时保留版本和修改人，不覆盖原稿或机器输出。
- 合成信中也避免真实电话、地址和学校名。研究目录及模型缓存只放 D 盘任务目录；结束时清理不再依赖的缓存和中间副本。

## 基线与可复现输出

`scripts/ocr-offline.py` 使用 PaddleOCR 官方 PP-OCRv6 Python 接口，或读取其已生成的 JSON；PaddleOCR 是**可选的、另行配置的**运行依赖，脚本不会自行安装。每页输出 SHA-256、尺寸、每行原识别文字、置信度、归一化四角坐标与低分提示。低分阈值只是人工复查队列提示，不能据此自动放行高分行。`completed` 仅表示模型运行结束，`humanReviewRequired` 始终为真。

例如，将成年合成样本和输出都放在 `D:\CodexData\work\riddle-ocr-study`：

```powershell
python -B scripts/ocr-offline.py --image 'D:\CodexData\work\riddle-ocr-study\adult-01.png' --output 'D:\CodexData\work\riddle-ocr-study\adult-01-ocr.json'
```

已有官方结果 JSON 时加 `--paddle-json`，可测试结构和坐标处理而不启动模型。运行前须先在 D 盘配置所需依赖和模型；模型首次下载的位置应核验，不能使用 C 盘默认缓存。官方接口与 `rec_texts`、`rec_scores`、`rec_polys` 字段见 [PaddleOCR 使用文档](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/OCR.html)。

## 对照和指标

1. A：PP-OCRv6 原始输出；B：加入拍摄质量门、漏页和行顺序检查；C：在 B 上对困难行重新裁切识别并保留不确定标记。每一版锁定模型、参数、样本集合和脚本版本。
2. 逐字比较忠实金标准，报告 CER、整行正确率、漏检行比例、原有错字被擅改率、低可信行召回率、端到端耗时及失败样例；按拍摄质量、倾斜和涂改分层。不能把官方内部指标当成本项目实测。
3. 成年参与者比较“仅原稿”“仅转写”“可追溯双视图”，完成找字、核对疑难行、理解内容等任务，记录误读数、完成时间和主观可读性。双视图不并排，点击转写行才定位对应原图；定位失败时保留普通切换。

## 投递安全门

OCR 文本和原图都可能含私人联系方式、地址、校名或二维码。若需要遮盖，应产生两份新的、相互绑定的不可逆展示副本，逐项核查后才能交给准确的收件人；原件仍在受限存储。模糊、漏行、坐标错误或风险未排除时保持待处理，不能根据识别成功直接送达。孩子的原字、错字和表达不可由模型润色。真实儿童拍摄、OCR、人工检查与收件展示的法律路径须先由合作学校和法律专业人员书面确认。
